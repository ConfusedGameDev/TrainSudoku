The XR scene is nearly empty

Assets/Scenes/XR.unity holds a light, the AR session, the hands rig, a placement object and one XRGame object. The signboard, maps, tray, board and wrist menu are all created in code by XRGame.Build. Your Unreal level will be just as empty, and for the same reason: almost everything is spawned from C++.

How Unreal organises a game

Actors and components

In Unity a GameObject is an empty container, and behaviour comes from the MonoBehaviours you attach. In Unreal the thing you place in a level is an actor, and an actor is a class you write. It owns components: a static mesh component draws a mesh, a scene component is a transform, a widget component draws UI in the world.

Two differences catch Unity developers:

  • An actor has no transform. Its root component does. Child objects in Unity become child components of one actor far more often than they become child actors.
  • Logic usually lives on the actor. Unity's board display is one MonoBehaviour that creates dozens of child GameObjects. In Unreal it is one ATsugiBoard actor with dozens of components, or a handful of instanced mesh components.

UObject, reflection and garbage collection

Unreal C++ is ordinary C++ with a reflection system bolted on by a code generator. Classes that derive from UObject and are marked UCLASS() are known to the engine: they can be saved, shown in the editor, used from Blueprint, and garbage collected.

The rule that matters on day one: a pointer to a UObject must be a UPROPERTY, or the collector does not know you are holding it and may delete the object under you. Plain C++ objects are not collected. You manage them with values, TUniquePtr and TSharedPtr.

This is why the rules code ports so cleanly. Board, Solver and GameFlow need none of that machinery, so they become plain C++ classes that only borrow the engine's containers.

Blueprint

A Blueprint is a class written as a graph. It can derive from a C++ class, which is the pattern this course uses throughout: C++ declares the class, its data and its heavy logic; a Blueprint subclass assigns meshes and sounds, tunes numbers, and wires events. That is the Unreal equivalent of a prefab with serialized fields, except the Blueprint is a real subclass.

Modules

A module is a folder of C++ with a .Build.cs file that lists what it depends on. It is the equivalent of an assembly definition. Unity's noEngineReferences: true becomes a module whose dependency list simply does not include Engine.

Steps

  1. Play the game. If a Quest build of the Unity edition is available, install it and finish the first station, Ashgate, which is the tutorial. If not, read section 4 of Docs/XR-PRD.md and play the rules demo in lesson 3.

  2. Read XRGame.cs top to bottom. Write down every other class it creates. You should end with roughly this list: XRBoardDisplay, XRPlatformMap, XRSignboard, XRWristMenu, XRPieceHands, XRTray, XRTutorialMarks, XRTutorialCallout, XRCuePlayer, plus XRBoardPlacement and XRIGrabInput from the scene.

  3. Sort that list. For each class decide: is it an actor, a component on another actor, a widget, or plain C++? There is no single right answer. Compare with the table in each later lesson when you reach it.

  4. Find the seams. The Unity code has three places where engine-free code calls out to the engine through an interface or a delegate. Find them, because you will port each seam as it stands:

    • ISaveStore: where progress is kept.
    • IGrabInput: how hands reach the game, whatever the hardware.
    • GameFlow.StarTimesForLevel: a delegate, because Core cannot see a level asset.

Knowledge check

The Unity board display creates one child GameObject per tile. What is the usual Unreal shape for the same thing?

  • One actor per tile, parented to a board actor.
  • One board actor that owns components, ideally one instanced mesh component for all the tiles.
  • One Blueprint per tile.

Actors are heavier than GameObjects and each ticks and replicates on its own. Thirty-six identical slabs are one instanced static mesh component, which is also one draw call. Lesson 7 builds it.

A Unity position is (2, 0.1, -3) metres. What is it in Unreal?

  • (200, 10, -300)
  • (2, -3, 0.1)
  • (-300, 200, 10)

Unity z becomes Unreal X, Unity x becomes Unreal Y, Unity y becomes Unreal Z, then metres become centimetres.

Why can GameFlow be a plain C++ class instead of a UObject?

  • It needs nothing the reflection system provides: it is not saved as an asset, not edited in the editor and not called from Blueprint directly.
  • Plain C++ classes run faster than UObjects.
  • State machines are not allowed to be UObjects.

A subsystem, which is a UObject, will own the flow and expose the few events Blueprint needs. Keeping the flow itself plain is what lets its 33 tests run without a world.

The board in the room

The board stops floating at a fixed spot and takes its place on a real table. It comes back to the same place next session. Two hands on a rail move, turn and scale it. This is where the Unreal port differs most from the Unity one, because the room features come from Meta's plugin instead of AR Foundation.

At the end
A placement controller with first placement, anchor restore, a two-hand handle, a height nudge and "re-place board".
On the headset
A ghost platform slides over your table; a pinch places the board there; restart the app and it is still there.
Unity equivalent
Milestone XR5, "Board in the room".

Unreal concepts

Scene data: the MR Utility Kit

AR Foundation's plane manager streams planes as it finds them. Meta's approach in Unreal is different: the headset keeps a scene model of the room from Space Setup, with labelled anchors such as TABLE, FLOOR and WALL_FACE. The MR Utility Kit (MRUK), part of the Meta XR plugin, loads that model and gives you room and anchor actors to query.

NeedMRUK
Load the roomLoadSceneFromDeviceAsync on the MRUK subsystem; an event fires when it is loaded

Enable Scene Support and Anchor Support beside Passthrough Enabled in the Meta XR settings. The app needs the runtime permission com.oculus.permission.USE_SCENE.

Spatial anchors

A spatial anchor is a pose the headset keeps fixed to the real world and corrects as its understanding of the room improves. In Meta's Unreal API an anchor is created on an actor: the plugin adds an anchor component and from then on keeps that actor's transform right. Anything attached to the actor follows. The anchor has a UUID you can save and later look up.

Asynchronous work without await

The Unity code is full of await anchors.TryAddAnchorAsync(...). Unreal C++ has no equivalent keyword in everyday use. An asynchronous engine call takes a delegate and calls it later. In Blueprint the same call is a latent node with separate output pins for success and failure, which reads almost like the C#.

That makes this a good place for Blueprint. The anchor and scene calls are few, they are all asynchronous, and they belong to a plugin whose API changes between releases. Put them in a Blueprint subclass, behind a small C++ interface that the rest of the game talks to.

Occlusion

A real gapThe Unity edition hides the board behind your real hands and furniture using environment depth, through custom shaders. In Unreal, Meta's Depth API offers soft occlusion, and Meta's documentation says soft occlusion requires Meta's fork of the engine. Hard occlusion works on the launcher engine but is marked deprecated since 5.5.

You are on the launcher engine, so decide this with your lead before writing code. The options:

OptionWhat the player seesCost
No occlusionThe board draws over your hands. Reaching "into" the board looks wrong.None

This course recommends hand masking for the first shipped version. Hands over the board is the case players notice. Record the decision; lesson 17 is where you would revisit it.

Steps

  1. Define what the game needs from the room. One small C++ class with events Blueprint can implement. Nothing outside it mentions Meta.

    A BlueprintNativeEvent has a C++ default, written as RequestRoom_Implementation, that a Blueprint may override. The defaults here report "no surfaces" and "anchor failed" at once, so the game runs in the editor with no headset.

  2. Implement it in Blueprint. Create BP_MetaRoomProvider deriving from UTsugiRoomProvider.

    • Request Room: request the Android permission com.oculus.permission.USE_SCENE; when granted, call the MRUK subsystem's load-from-device function; on its loaded event, tell MRUK to generate collision meshes for the room's anchors and broadcast OnRoomReady(true). On refusal or failure broadcast false.
    • Try Hit Surface: raycast against the current room; accept the hit when its normal points up.
    • Anchor And Save: Create Spatial Anchor on the actor, then Save Anchors, then broadcast the UUID as a string.
    • Load Anchor: Discover Anchors filtered by the UUID; on a result, spawn an empty actor, bind the anchor to it, and broadcast it.
    • Erase Anchor: Erase Anchors by UUID.

    Not confirmedThe exact MRUK node names, the name of its loaded event, and how a discovered anchor is bound to a new actor were not checked node by node for plugin 207. Meta's MRUK and spatial-anchor sample projects show each of these flows; build from those.

  3. Write the placement controller in C++. It is a state machine over the provider. Make it an actor, ATsugiBoardPlacement, that owns the board root: an empty scene component the board, map, signboard and tray all hang from.

    Functions bound to dynamic delegates must be UFUNCTIONs. That is why the three handlers are marked.

  4. Port the ghost. Every frame while locating, aim from the hand, then fall back to floating. The platform's near edge is the one nearest the player.

    GetAim tries the right hand, then the left, then the head, as the Unity code does. No ray is ever drawn. SelectPressedThisFrame is a pinch closing on either hand, or a trigger press; this is the one place the trigger is used.

  5. Anchor in the right order. When the board is re-anchored after a move, a new anchor actor is created while the old one still exists.

    The preference keys in Unity are tsugi.xr.boardAnchor, tsugi.xr.boardCell and tsugi.xr.boardOnSurface. They sit beside the wrist menu's settings, never in save.json.

  6. Port the handle's maths. One hand on the rail only lights it. With two, their midpoint carries the board, the line between them steers it, and their spread scales it. The board follows only once the hands leave a dead zone, which removed the false moves a single pinch kept causing.

    Either hand letting go ends the move. If the pair never left the dead zone, nothing moved and nothing is re-anchored.

  7. Draw the rail. The Unity rail is a rounded tube wrapped round the near corner on the side away from the tray. When touched it lights and opens along the near edge and round the far corner, so there is an end for each hand, and folds back after 0.8 seconds alone. Build it as a procedural mesh, or as three static mesh segments you show and scale. A fingertip or pinch within about 2 cm of it counts as touching; it stops counting beyond 5 cm.

  8. Hand masking. If your team chose it: make an unlit, opaque material whose colour output is black with alpha zero in the framebuffer and which writes depth, and apply it to the hand meshes in BP_TsugiPawn. With passthrough as an underlay, pixels the hand covers show the real hand.

    Not confirmedThe exact material settings that leave a passthrough "hole" depend on how the mobile renderer handles alpha in your configuration. Meta's passthrough samples include a working masking material; start from it.

  9. The shadow catcher. A board resting on a real table should darken it. Add a plane just above the surface, three cells wider than the board on every side, with a material that outputs only shadow. Show it only when IsOnSurface() is true: a shadow under a floating board reads as a fault.

Your port

  • The rest of ATsugiBoardPlacement: the settle delay, restore, Replace, Nudge with its 0.6-second settle and its refusal to go below a surface, and SettleOnSurface.
  • ATsugiBoardHandle or a component: touch detection, the two-hand carry, Claims(point) for lesson 11, SetAvailable, and the footprint that changes with the board's size.
  • The placement sign: a short line of text floating 0.8 m ahead of the eyes. Two messages: place on the surface, or no surface found.
  • Move the board, in the level, under the placement's board root. From now on the game starts when OnPlaced fires: that is when the subsystem's flow gets ShowNetwork().

Acceptance checks

  • First run: a permission prompt appears, then a ghost follows my hand's aim across my table and sits flat on it.
  • With the permission refused, the ghost floats ahead of me at waist height and a pinch still places the board.
  • A pinch places the board with its near edge towards me.
  • Quitting and relaunching restores the board in the same place and at the same size, with no ghost.
  • In a different room, the saved anchor is not found and first placement runs again.
  • One hand on the rail lights it and moves nothing. Two hands move, turn and scale the board; cell size stays between 4 and 9 cm.
  • Released within 5 cm of the table, the board settles onto it. Released in the air, it stays there.
  • After a handle move, a relaunch restores the new place, and no second board or stale anchor appears.
  • My team's occlusion decision is written down, and what we chose works.

Pitfalls

  • The scene permission can be lost in the manifest. The Unity build hit a package bug where one permission request overwrote another and plane detection never started, silently. If your room never loads, check the merged manifest in the APK for USE_SCENE before debugging code.
  • No Space Setup, no scene. A headset that has never scanned the room returns an empty scene model. The Unity build shows a hint after 6 seconds without a surface. Keep that hint.
  • A grab that detaches. In Unity, making the handle a grabbable object detached it from the board for the length of the grab and left it hanging in the air. Your handle moves the board in its own code; do not let any physics or attachment helper take ownership of it.
  • Scale while detached. While the handle carries the board, the root is detached from its anchor, so its relative scale is its world scale. Re-attach with keep world transform.
  • Keep the room's colliders. Hide the generated room meshes but leave their collision on. Thrown pieces bounce off the real table in lesson 11.

Knowledge check

The board is re-anchored after a move. In what order?

  • Destroy the old anchor, create the new one, attach the board.
  • Create the new anchor, attach the board to it, then destroy the old one.
  • Order does not matter.

Destroying an anchor's actor destroys what is attached to it. The Unity code documents the same rule after losing a board to it.

Why are the Meta scene and anchor calls in a Blueprint behind a C++ base class?

  • They cannot be called from C++.
  • They are asynchronous, few, and tied to a plugin whose API moves; isolating them keeps the game's C++ independent of the plugin and runnable in the editor without a headset.
  • Blueprint is faster for asynchronous code.

The C++ functions exist and are listed above. Using latent nodes is a choice about where change is cheapest.

A player grabs the rail with one hand and pulls. What happens?

  • The board follows the hand.
  • The rail lights and opens out; the board does not move.
  • The board scales.

Single-pinch moves were false positives in the headset checks. Moving needs both hands and a deliberate motion past the dead zone.

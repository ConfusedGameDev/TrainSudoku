Station UE 01

Toolchain and first build on the headset

You install the engine, the Android toolchain and the Meta XR plugin, create the project with its three modules, and put an empty app on the Quest. Device deployment should be routine long before the last lesson.

At the end
A C++ project named Tsugi with modules TsugiCore, TsugiXR and TsugiEditor, in source control.
On the headset
A cube floating half a metre in front of you, in VR.
Unity equivalent
Milestone XR2, "XR foundation".

Unreal concepts

The project file and its modules

A .uproject is a small JSON file. It lists the project's modules and the plugins it switches on. C++ lives under Source/, one folder per module. Two more files, Tsugi.Target.cs and TsugiEditor.Target.cs, say which modules go into the game and which into the editor.

Unreal Build Tool reads those files and drives the compiler. You never edit a Visual Studio project by hand: the .sln is generated, like Unity's .csproj files, and stays out of source control.

Plugins

A plugin is a bundle of modules and content. Engine plugins live under the engine's Plugins/ folder and must be prebuilt for exactly your engine version. Project plugins live under your project's Plugins/ folder and are compiled with your project. That difference matters in step 4.

Cooking and packaging

Unity builds a player. Unreal cooks assets into the target platform's formats, then packages them with the compiled code into an APK. Cooking only includes assets that something references, starting from the maps you list. An asset nothing points at is silently left out. You will meet this again in lesson 4.

Steps

  1. Install the engine. In the Epic Games Launcher, install Unreal Engine 5.8. Open Options on the install and tick Android under target platforms. Without it you cannot package for Quest.

  2. Install the Android toolchain. Unreal ships a tool called Turnkey that installs the right SDK, NDK and JDK for your engine. Open any project, then Platforms > SDK Management > Android > Install SDK. Accept the licences when asked. Restart the editor afterwards.

    If you prefer to do it by hand, install Android Studio at the version above and follow Epic's manual setup page. Then set the paths in Project Settings > Platforms > Android SDK.

  3. Prepare the headset. Create a Meta developer account, enable developer mode for the headset in the Meta Horizon phone app, connect by USB and accept the debugging prompt inside the headset. Install Meta Quest Developer Hub. Confirm the PC sees the device:

  4. Install the Meta XR plugin, and check it loads. Download version 207.0 or later from Meta's "Unreal Engine 5 Integration" page. Meta's instruction is to unzip it into the engine: C:\Program Files\Epic Games\UE_5.8\Engine\Plugins\Marketplace\, creating Marketplace if it is not there.

    Known problemMeta's own tracker has an open report, "Meta XR plugins version mismatch with Unreal Engine 5.8". Some downloads that claim 5.8 were built for 5.7.0. The symptom is a version warning on start, then modules such as MetaXRHaptics and OculusInteraction failing to load with "Engine modules cannot be compiled at runtime". At the time of writing its status was "Investigating", with no fix version.

    If you hit it, work down this list:

    • Confirm the download really is 207.0 or later. Earlier ones targeted 5.7.
    • Move the plugin into the project. Copy the plugin folder to Tsugi/Plugins/MetaXR/ and delete it from the engine. A project plugin is compiled from source with your project, so a binary built for the wrong engine no longer matters. This only works for a C++ project, which yours is.
    • If source in the package does not compile against 5.8 either, stop and tell your lead. The fallbacks are UE 5.7.x with its matching plugin, or building Meta's fork of the engine from GitHub. Both change the course's engine version and are a team decision, not yours alone.

    Not confirmedMoving the plugin into the project is the standard cure for this class of error, but it was not tried against the 207.0 package for this course.

  5. Create the project. In the Unreal Project Browser choose Games > Blank, C++, target platform Mobile, quality preset Scalable, starter content off. Name it Tsugi. Put it next to the Unity repository, not inside it.

    Why not the VR templateThe VR template comes with teleport rays, grab components and a menu laser. The Unity edition spent a milestone removing exactly those from XRI's sample rig, because a ray reaching for one thing kept catching another. Start blank and add only what the game uses.

  6. Rename the game module and add two more. The wizard made one module called Tsugi. Close the editor and Visual Studio, then make Source/ look like this:

    Each module needs one .cpp that registers it. Exactly one module in a project is the primary game module.

    Now tell the project and the two targets about them.

    Delete Binaries/, Intermediate/ and the old .sln. Right-click Tsugi.uproject and choose Generate Visual Studio project files. Build the Development Editor configuration. Open the project.

  7. Switch on the plugins. Edit > Plugins: enable Meta XR, OpenXR and OpenXR Hand Tracking. Restart when asked. Then Edit > Project Settings > Plugins > Meta XR:

    • General > XR API: Epic Native OpenXR (Recommended).
    • Mobile > Supported Meta Quest Devices: add Quest 3 and Quest 3S. The Unity build targets only those two.
    • Click Launch Meta XR Project Setup Tool and apply what it recommends. It sets the renderer, MSAA, multiview and Vulkan for you. Lesson 17 goes back over what each one does.

  8. Set the Android basics. In Project Settings > Platforms > Android, press Configure Now if the banner asks, then:

    SettingValueWhy
    Android Package Namecom.GorillaGonzalez.Tsugi.XR.UEThe Unity build is com.GorillaGonzalez.Tsugi.XR. A different id lets both sit on one headset while you compare them.

    In Project Settings > Project > Description, tick Start in VR.

  9. Make the level. File > New Level > Empty Level. Save it as Content/Maps/L_Tsugi. Add a directional light and a cube scaled to 0.1, placed at (50, 0, 120): half a metre ahead and 1.2 m up. Set it as both Editor Startup Map and Game Default Map in Project Settings > Maps & Modes, and add it to Packaging > List of maps to include in a packaged build.

  10. Launch on the device. With the headset connected, use Platforms > (your Quest under Android) > Launch, choosing ASTC textures. The first run compiles shaders and takes a long time. Later runs are much faster.

    Watch the log while it runs. Stream it live rather than dumping it afterwards: on the Unity side the headset's own services filled the log buffer within seconds, and a dump taken later had already lost the app's lines.

  11. Put it in source control. Commit Tsugi.uproject, Config/, Content/, Source/ and, if you moved it there, Plugins/. Ignore Binaries/, Intermediate/, Saved/, DerivedDataCache/, .vs/ and *.sln. Use Git LFS for *.uasset and *.umap: they are binary.

Your port

There is no Unity code to port here. The exercise is to make the build repeatable: write a one-page BUILDING.md in the new repository that takes a teammate from a clean machine to the cube on the headset. Have a teammate follow it without your help.

Acceptance checks

  • The editor opens the project with no plugin or module load errors in the Output Log.
  • All three modules appear in Tools > Debug > Modules.
  • TsugiCore.Build.cs lists only Core and CoreUObject.
  • The app installs on a Quest 3 or 3S and shows the cube, tracked, in stereo.
  • I can see the app's log lines live with adb logcat.
  • A teammate reproduced the build from BUILDING.md alone.

Pitfalls

  • Editing the wrong settings. On the Unity side, the Player settings edit whatever build profile is active, so XR settings were once written into the phone's profile. Unreal has one set of project settings with per-platform overrides in Config/Android/. Know which file a change lands in: look at the diff before you commit.
  • The first launch looks hung. It is compiling shaders. Give it time before you kill it.
  • Hot reload versus Live Coding. Use Live Coding (Ctrl+Alt+F11) for changes inside function bodies. After changing a header, a UPROPERTY or a class layout, close the editor and build from the IDE. Skipping this corrupts Blueprints that derive from the class.

Knowledge check

Why does moving a plugin from the engine folder into the project folder fix a "built for a different engine version" error?

  • The project folder is searched first, so the engine never sees the bad one.
  • Project plugins are compiled from source with the project, so the prebuilt binary is no longer used.
  • It does not. The plugin must always live in the engine.

An installed engine cannot compile engine plugins, which is what "Engine modules cannot be compiled at runtime" means. A C++ project can compile its own.

You add a texture to Content/ and nothing references it. Is it in the APK?

  • Yes, everything under Content/ is packaged.
  • No. The cooker only includes what is reachable from the maps and assets it was told to start from.

This is the opposite of Unity's Resources folder. Lesson 4 depends on it: 216 level assets must be reachable or they will not ship.

What stops someone adding an engine dependency to the rules code by accident?

  • A code review.
  • TsugiCore.Build.cs does not list Engine, so including an engine header fails to compile or link.
  • Nothing; it is a convention.

Same guarantee as noEngineReferences on the Unity assembly, enforced by the build.

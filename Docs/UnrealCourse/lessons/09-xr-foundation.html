Station UE 09

XR foundation

You build the player: a head, two hands that work as tracked hands or as controllers, and passthrough so the board sits in the real room. Then you reduce all of that hardware to two points per hand, which is all the game ever asks for.

At the end
A pawn with a camera and two motion controllers, a component that reports each hand's fingertip and pinch point every frame, and the grab interface declared.
On the headset
Your room in passthrough, the board floating in it, and a small sphere on each index fingertip and each pinch point, with hands or with controllers.
Unity equivalent
Milestone XR2, plus the input half of XR6.

What the Unity edition learned about input

The Unity build started on the XR Interaction Toolkit's sample rig and ended up using very little of it. Read this before you design anything, because every item cost a headset check to find.

  • No rays, anywhere. A ray reaching for one thing kept catching another: RESUME was pressed from across the room, the handle was grabbed by accident. Since 15 September 2026 everything is taken by a close pinch or grip, and every menu is pressed with a fingertip.
  • The toolkit's poke never pressed a button on the headset. The game reads fingertip positions itself and decides what a press is.
  • The sample rig switched rays back on by itself, so the game disables them every frame.
  • The game already hides the toolkit behind one interface, IGrabInput. Nothing in the rules or the board knows which SDK is underneath.

For you this is good news. You do not need an interaction framework. You need two positions per hand and a way to know when a pinch or grip starts and ends. Starting from a blank project means there are no rays to remove.

Unreal concepts

The pawn

The player's body is a APawn. For XR it has a root scene component that stands for the origin of the tracking space, a camera component the headset drives, and one UMotionControllerComponent per hand. A motion controller component follows a named motion source, Left or Right, and it follows whichever is active: the controller, or the tracked hand.

The game mode

The game mode says which pawn class to spawn. Make a Blueprint subclass of your pawn so meshes and effects can be assigned in the editor, then a Blueprint game mode that names it, and select that game mode in Project Settings > Maps & Modes.

Enhanced Input

Unreal's input system has two asset types. An Input Action is a named intent with a value type: IA_GripLeft, a float. An Input Mapping Context binds actions to physical keys: "Oculus Touch (L) Grip Axis". You add a mapping context to the local player at start, then bind C++ functions to actions. It is the same idea as Unity's Input System action maps.

Hand tracking through OpenXR

With the OpenXR Hand Tracking plugin on, the engine exposes 26 joints per hand in world space. You read them through the head-mounted display function library. Meta's plugin adds its own hand component for drawing the hand mesh, which is useful as a visual and which you can add in the pawn's Blueprint without your C++ depending on Meta's modules.

Passthrough

Passthrough is a compositor layer drawn behind your scene. Your scene must leave the background transparent: no sky, nothing clearing to an opaque colour. Meta's plugin provides a subsystem that creates a persistent passthrough layer for the life of the app.

Steps

  1. Add the module dependencies. In TsugiXR.Build.cs add "HeadMountedDisplay" and "EnhancedInput". Regenerate project files. If a header in this lesson is not found, search the engine source for it and add the module whose folder it sits in; XR headers have moved between modules across 5.x.

  2. Declare the pawn.

    Check in your engineEHMDTrackingOrigin gained and renamed values across 5.x. If LocalFloor is not there, use Stage. Either puts the floor at zero.

  3. Make the Blueprints. BP_TsugiPawn deriving from ATsugiPawn, and BP_TsugiGameMode deriving from AGameModeBase with its Default Pawn Class set to the pawn. Select the game mode in Project Settings. In the pawn Blueprint, add Meta's hand component under each motion controller for the hand visual, and a controller model for when controllers are in use.

    In Project Settings > Plugins > Meta XR > Mobile, set Hand Tracking Support to Controllers and Hands and Hand Tracking Frequency to High.

  4. Switch passthrough on. In the same settings page set Passthrough Enabled. Remove any sky or fog from L_Tsugi. In BP_TsugiPawn's Event BeginPlay, add Get Oculus XR Passthrough Subsystem and call Initialize Persistent Passthrough with Layer Placement set to Underlay.

    This is a Blueprint job on purpose. It is three nodes of setup, it touches only a plugin, and it keeps the Meta module out of your C++ dependency list for now.

    Store ruleCheck IsPassthroughRecommended if you ever add a fully virtual mode. And note VRC.Quest.Functional.14: a passthrough app must show a passthrough loading screen, not a black one. Set System Splash Screen Background to Passthrough (Contextual) in the Meta XR settings.

  5. Create the input assets. Three Input Actions: IA_GripLeft and IA_GripRight (Axis1D float) and IA_Menu (bool). One mapping context, IMC_Tsugi, binding them to the left and right Touch grip axes and the left Touch menu button. Assign the context on BP_TsugiPawn.

  6. Read the hands. This component is the port of XRTouchPoints. Once a frame it works out, for each hand, whether it is tracked, where its fingertip is, where its pinch point is, and whether it is holding.

    Check in your engineGetHandTrackingState and FXRHandTrackingState replaced the older GetMotionControllerData around 5.5. The field names here are from memory. Read HeadMountedDisplayFunctionLibrary.h and HeadMountedDisplayTypes.h and use what they declare. The pinch thresholds are starting values chosen for this course, not numbers from the Unity build, which took its pinch from the toolkit. Tune them on the headset.

  7. Feed the grips from Enhanced Input. In the pawn, override SetupPlayerInputComponent, cast the component to UEnhancedInputComponent, and bind IA_GripLeft and IA_GripRight for the Triggered and Completed events to functions that call Hands->SetGrip. Bind IA_Menu to a multicast delegate on the pawn, OnMenuPressed, which lesson 14 listens to.

  8. Declare the grab interface. Port IGrabInput now so the next two lessons have it. The distant-hold fields are left out: they exist in Unity for a ray that Quest no longer has.

    Lesson 11 implements it on top of UTsugiHandsComponent.

Your port

  • ReadController, and a choice of where the controller's "fingertip" is. Try it against a cube: the tip should be where you naturally poke with the controller.
  • The Enhanced Input bindings and OnMenuPressed.
  • A console variable, Tsugi.DrawHands 1, that turns bDrawPoints on. You will use it in every remaining lesson.

Acceptance checks

  • On the headset I see my room in passthrough with the board from lesson 7 in it, and no black background at any point after the splash.
  • With controllers down, a sphere sits on each index fingertip and each pinch point, and follows them without visible lag.
  • Pinching turns that hand's pinch sphere green; it does not flicker when I hold my fingers almost together.
  • Picking the controllers up moves the spheres to the controllers; squeezing a grip turns the sphere green.
  • Putting the controllers down returns to hands within a second or two.
  • The left menu button logs a line through OnMenuPressed.
  • There is no ray, laser or teleport arc anywhere.

Pitfalls

  • World space depends on the pawn. Joint positions in "Unreal world space" already include the pawn's transform. If you move the pawn, they move. Leave the pawn at the tracking origin; the board moves, the player does not.
  • The system gesture is reserved. The palm-up pinch belongs to the operating system (VRC.Quest.Input.8). The wrist menu in lesson 14 sits on the back of the wrist for that reason.
  • Hands vanish near each other and near the table. Tracking drops when one hand covers the other. Treat bTracked going false as "let go", never as "keep the last pose".
  • Testing without the headset. VR Preview over Link works for hands and controllers but not for every mixed-reality feature. For anything that involves the room, package to the device.

Knowledge check

Why does the game define its own pinch point instead of using an interaction framework's grab?

  • Frameworks cannot detect pinches.
  • The game needs only two points and a held flag per hand, and the Unity edition found that framework rays and pokes misfired on the headset. A small interface keeps the rest of the game independent of the SDK.
  • Meta forbids third-party interaction frameworks.

The interface also makes a later port to other hardware a matter of writing one new implementation, which is what the Unity project planned for Vision Pro.

A pinch closes at a 2 cm gap. Why does it not open again at 2 cm?

  • Tracking noise near the threshold would toggle the hold many times a second; a wider opening gap gives it room.
  • Fingers cannot physically reopen to 2 cm.

The same idea appears in the Unity code as WatchCheck (show at 45°, hide at 65°) and in the handle's touch and let-go distances.

The background behind the board is black on the headset. Which is the least likely cause?

  • A sky sphere left in the level.
  • Passthrough not enabled in the Meta XR settings.
  • The board's materials are opaque.

Opaque objects are meant to cover passthrough. A black background means either the layer was never created or something is filling the frame behind everything.

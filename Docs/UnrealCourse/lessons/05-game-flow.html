Game framework and flow

You port the state machine that runs the whole game, with its clock and its progress rules, and give it a home in Unreal's game framework. The Unity shell owned the flow from a MonoBehaviour; yours lives in a game instance subsystem.

The flow you are porting

GameFlow has seven states. Every method checks the state it is called in and refuses anything else, because the UI should only ever offer what is valid.

The XR edition never shows the main menu. Once the board is placed in the room, XRGame calls ShowNetwork() straight from the initial MainMenu state. Board placement is a precondition held by the shell, not a flow state.

Stars and unlocking

  • A level has two thresholds in seconds. At or under the first: three stars. At or under the second: two. Anything else, including a level with no thresholds: one.
  • Best time and best stars are stored separately. A slower run lowers neither.
  • A station is open when the level before it in the flat list has a best time. The first is always open.
  • A line is open when every station on the line before it has at least one star. The first line is always open.
  • Nothing about unlocking is stored. It is worked out from times and stars on every call.

Unreal concepts

The game instance and its subsystems

A UGameInstance is created when the app starts and destroyed when it quits. It survives level loads, which a GameMode does not. A subsystem is a UObject the engine creates automatically alongside an owner and destroys with it. Declare a class deriving from UGameInstanceSubsystem and one instance exists for the life of the app, reachable from anywhere:

That is the Unreal answer to a singleton MonoBehaviour on a "Game" object, with a defined lifetime and no scene object to forget.

Delegates

C# events become delegates. There are four kinds, and choosing wrongly is a common first mistake.

KindListenersBlueprintUse here
TDelegate<Sig>OneNoA callback handed to one function
TMulticastDelegate<Sig>ManyNoEvery event on the plain C++ flow
DECLARE_DYNAMIC_MULTICAST_DELEGATE…ManyYesWhat the subsystem re-broadcasts for Blueprint and widgets
TFunction<Sig>OneNoA seam, such as StarTimesForLevel

A listener keeps the FDelegateHandle that AddLambda or AddUObject returns and removes it when it goes away. AddUObject is safer than a lambda capturing this: the delegate skips an object that has been destroyed.

Ticking something that is not an actor

The flow's clock needs time every frame. A subsystem does not tick by default. Inheriting from FTickableGameObject as well gives it a Tick without needing an actor in the level.

Steps

  1. Port the save store interface. A C# interface becomes an abstract class. It is plain C++, so it does not use Unreal's UINTERFACE machinery, which exists for Blueprint.

    TrapTMap<FString, …> compares keys without regard to case by default. Unity's dictionary is case-sensitive. The shipped ids are all lower case, so it does not bite today, but write a test with two ids that differ only by case and decide deliberately what your store does.

  2. Declare the flow. Events become multicast delegates, the two seams become TFunctions, and every transition returns bool where the C# returned void and threw.

  3. Translate "throws on an invalid transition". This is the pattern for the whole file.

  4. Create the subsystem. It does what XRGame.BuildFlow does: loads the network, builds the id list, creates the store and the flow, connects the star-time seam and runs the save migration.

    The lambda that captures this lives on the flow, and the flow is destroyed in Deinitialize before the subsystem goes, so it cannot outlive what it captured. State that reasoning in a comment whenever you capture this.

  5. Drive it without a UI. Console commands let you walk the flow from the editor's console now, and from the headset later.

    Press Play in the editor, open the console with the backtick key, and type Tsugi.Network, Tsugi.Line 0, Tsugi.Start 0. Watch the Output Log.

Pitfalls

  • The class default object ticks too. Unreal creates one default instance of every UCLASS. It is also an FTickableGameObject. IsTickable() returning false while Flow is unset is what keeps it quiet.
  • Pausing must not resume by itself. In the Unity headset checks, the game once resumed on its own after a focus loss. The rule since then: only an explicit RESUME calls ResumeGame. Do not add a convenience that resumes on regaining focus.
  • Star times are read once per level start. Begin is the only caller of the seam, on purpose. Do not call it from Tick.
  • ensure breaks into the debugger. With a debugger attached, each expected failure in a test stops execution. Run the suite without the debugger, or continue past them.

Knowledge check

Why does the flow live in a game instance subsystem and not in the game mode?

  • Game modes cannot hold plain C++ objects.
  • The game mode is destroyed and recreated with each level load; the game instance lasts for the whole run of the app.
  • Subsystems tick faster.

Tsugi uses one level, so either would work today. The subsystem is the choice that stays right if that ever changes, and it needs no actor in the level.

A level has thresholds of 96 and 192 seconds. The player finishes in exactly 96.0 seconds. How many stars?

  • Three
  • Two

StarsFor uses seconds <= three. The boundary belongs to the higher rating.

The subsystem holds Network in a UPROPERTY() with no specifiers. What is that for?

  • To show it in the editor.
  • To tell the garbage collector the subsystem references it, so it is not freed.
  • To save it in the save file.

An empty UPROPERTY() is purely a reference the collector can see.

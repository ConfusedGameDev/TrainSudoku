Tutorial

The first station teaches the game by walking the player along its own solution, staging two mistakes on purpose. The script is not written against that level: it is read off the board. This lesson has almost no new Unreal in it. It uses everything you have built.

The script

The coach solves the level once, walks the solution from S to E, and keeps the cells the player must fill, in order, with the key each needs. Its target is always the first of those still empty.

Until the erase lesson is done the coach is locked. Its Admits function is the Gate on FTsugiPieceDrop from lesson 11: a legal drop anywhere else comes back Steered, with a soft note and not the error sound.

How the script reads itself off the board

  • The adjacency mistake: the first key, in enum order, that is illegal on the second rail's cell. If every key fits there, the lesson is skipped.
  • The overfill mistake: an empty cell off the route where exactly one key is legal, and where the row or column is already at its clue, so one more rail overfills it. The nearest such cell to the last rail laid wins. If the board has none, the coach unlocks instead of stalling.
  • A resumed board: if the board already holds player pieces when the level loads, the coach starts unlocked. Re-locking would punish coming back.
  • Finding erase alone: if the player lifts any rail before being asked, the detour has nothing left to teach, and the coach unlocks.

Nothing here mentions a coordinate. Replace Ashgate with another board and the tutorial rewrites itself.

Unreal concepts

Two small ones, both about putting pieces together.

Composition over inheritance

The tutorial adds no new actor type that knows about the game. It adds a plain rules object, two small display actors, and three or four lines in the shell that pass facts between them. That is the same shape as every feature so far, and it is why each one could be tested on its own.

Function objects as seams

FTsugiPieceDrop::Gate is a TFunction. The shell assigns a lambda that asks the coach. Neither the drop rules nor the coach knows the other exists. You have now used this pattern five times: star times, line unlock override, the handle's claim on a pinch, the board for saving, and this gate.

Steps

  1. Port the coach and its tests. It is the largest single rules file, 429 lines, and it is all plain logic over FTsugiSolver, FTsugiPathFinder and FTsugiLegality. The gate is the part to read closely.

    The coach keeps a pointer to the board it was given in Begin. Like the drop rules, it must be told again on every level start and must not be used after the board is cleared.

    Key, the line to print, is a string such as xr.tutorial.lay_first. Keep those 22 key names exactly. Lesson 16 looks them up in the string table.

  2. Solve on the headset, once. Begin runs the solver when the tutorial level loads. Ashgate is small and it finishes at once. Still, measure it on the device: log the node count and the time. This is the only place the solver runs in a shipped build.

  3. Feed the coach. In the shell's HandleActed, after the board display has been synced, pass each result to the coach with two facts from the board, then refresh what is shown.

    Then three more connections, all one line each:

    • On level start: bTeaching = Level->bIsTutorial, then Coach.Begin(Data, Board, bTeaching).
    • The gate: PieceHands->Gate = [this](int32 X, int32 Y, ETsugiPieceKey Key) { return !bTeaching || Coach.Admits(X, Y, Key); }.
    • On entering TrainRun: Coach.Complete(). On entering Network or LevelSelect: bTeaching = false.

  4. Draw the rings. One ring on the target cell and, when the guide names a slot, one on that tray slot. A flat ring mesh, slowly pulsing in scale, in the line colour. The Unity project keeps the phone's ring in its own group on the board, because the board's routine redraw wiped anything stored with the selection markers. Your equivalent: the rings belong to their own small actor and nothing else clears them.

  5. Stand the callout up. A small widget component, 900 × 420 pixels, 18 cm wide at the standard cell and sized in cells so it scales with the board. Its bottom edge stands 2.2 cells above the target cell, clear of a hand coming down. It turns to face the head like the clue signs.

    It has no buttons and must never be in a hand's way: no collision, and no press component. Attach it under the board root, not under the board, so the pause's dimming does not touch it; it hides in pause anyway.

  6. The briefing. Three cards of rules on the signboard, shown once per session, the first time the tutorial station loads with no player rails on it. Each has a title, a body and a button: NEXT, NEXT, START. While a card is up the board is live underneath; the cards are on the sign, not over the board. Keep the "once per session" flag on the subsystem so it outlives level changes.

  7. Hold the tutorial to one station. Extend the level test from lesson 4 with the two checks from LevelCollectionTests: exactly one level has the flag, and that level's guided path offers both a one-key cell and a choice. Add one more of your own: Coach.Begin on the shipped tutorial level yields an adjacency lesson and an overfill cell, so the script you ship has every stage.

Acceptance checks

  • Tsugi.Core.TutorialCoach tests pass.
  • On a fresh save, Ashgate opens with the three briefing cards; they do not show again that session.
  • Rail 1: a slot and a cell are ringed. A legal drop on any other cell flies back with the soft note and no error sound.
  • Rail 2: the ringed slot's piece shows a red ghost on the ringed cell and flies back; the callout then explains, and the right slot lights.
  • After three rails, a cell off the route is ringed. The one piece that fits turns a clue red.
  • The callout asks me to lift it; lifting it changes the callout to "throw it away".
  • From then on any legal drop anywhere is accepted, and the ring keeps pointing at the next cell of the route.
  • Leaving mid-tutorial and returning restores my rails with the coach unlocked.
  • A person who has never seen the game finished Ashgate without my help. I watched and wrote down where they hesitated.
  • No other station shows rings, a callout or a briefing.

Pitfalls

  • Order of the two facts. Observe must see the board as it is after the action: overfull, and just-satisfied. Call it after Sync, never before. The phone version of this bug wiped a "clue satisfied" note with the very placement that earned it.
  • The callout in a hand's way. It stands 2.2 cells up for a reason. If it has any collision, or sits lower, hands knock into it or the grab component hesitates.
  • The quick-test aid. Tsugi.QuickRails must never apply to the tutorial level. A pre-laid board leaves the walkthrough nothing to walk.
  • Hover and release must agree. A drop the gate refuses must show the red ghost while hovering. That is why the gate lives inside the drop rules and both Hover and Release consult it.

Knowledge check

During the first rail the player drops the correct piece on a different cell where it is perfectly legal. What happens?

  • It is placed; legal is legal.
  • It flies back, marked Steered, with a soft note and no error cue.
  • It flies back with the error cue.

While locked, the gate admits only the drop being asked for. A steered return is not a mistake, so it does not sound like one.

Why does the coach find its "mistake" cell by searching the board at runtime?

  • To save memory.
  • So the script is not tied to one level's coordinates: any board marked as the tutorial writes its own walkthrough, and tests can run it on small made-up boards.
  • Because level assets cannot store coordinates.

The Unity tests use tiny boards from XRTestBoards.cs. A script written against Ashgate could only be tested on Ashgate.

A player in the middle of the locked stage lifts one of the rails they already laid, unprompted. What does the coach do?

  • Refuses the lift.
  • Puts the rail back.
  • Unlocks: the player has found erasing alone, so the detour has nothing left to teach.

Lifts are never gated. The tutorial exists because lifting to erase is the one thing the board does not show you how to do; someone who does it already knows.

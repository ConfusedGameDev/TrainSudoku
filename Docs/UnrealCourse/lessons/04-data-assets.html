Station UE 04

Data assets and the level pipeline

The game ships 24 lines of 9 stations: 216 levels, stored in Unity as ScriptableObjects. You define the matching Unreal asset classes, export the data from Unity as JSON, import it with an editor script, and prove every board still has exactly one solution.

At the end
216 level assets, 24 line assets and one network asset under Content/Data/Levels, in the same order as Unity, verified by a test.
On the headset
Nothing new, but the levels are now in the build.
Unity equivalent
Milestones M1 and M10, plus the network work of M11 onwards.

The rule you must not break

Save identityA level is identified in the save file by its id string. A level's position in the game is its index in one flat list: every line's stations concatenated in line order. Lines and stations are only a view over that list.

So the import must keep each id exactly, keep the lines in the same order, and keep the stations in the same order within each line. Inserting or reordering a line renumbers every level after it.

Unreal concepts

Data assets

A UDataAsset subclass is the direct equivalent of a ScriptableObject: a class with UPROPERTY fields, saved as a .uasset, edited in the Details panel. UPrimaryDataAsset adds an identity the Asset Manager understands, which you need for the next point.

Hard and soft references

TypeLoads the targetUse for
TObjectPtr<T> in a UPROPERTYWith the owner, alwaysA line's nine levels. They are tiny and always needed.
TSoftObjectPtr<T>Only when you askThe pointer from project settings to the network. Large content you load on demand.

Use TObjectPtr<T> where you would have written T* in a reflected field. It behaves like a raw pointer in a shipped build and adds checks in the editor.

The Asset Manager and cooking

The cooker starts from your maps and follows hard references. The network asset is referenced by no map, so on its own it would not be packaged, and neither would anything it points to. You fix that by registering it with the Asset Manager as a primary asset type that is always cooked. Everything it references by hard pointer then comes along.

Editor scripting in Python

The Unreal editor embeds Python with an unreal module that mirrors the reflected C++ API. Reflected names are converted: a C++ property ColumnClues is column_clues in Python, and bIsTutorial is is_tutorial. It is the quickest way to create a few hundred assets from a file.

Steps

  1. Declare the three asset classes in TsugiXR. They hold engine types, so they cannot live in TsugiCore. Unity's LevelCollection was only a list wrapper; a line holds its levels directly.

    Build, then confirm in the Content Browser that Add > Miscellaneous > Data Asset offers all three classes.

  2. Export from Unity. Drop this file into the Unity project's Assets/01.Scripts/XR/Editor/ folder, run Window > TrainSudoku > XR > Export Network JSON, and remove it again unless your team wants to keep it. It walks Network.asset, so levels no line references, such as Hard.asset, are correctly left out.

    Enum values are written as names, not numbers. A file that says "key": "NE" can be checked by eye; one that says 3 cannot.

  3. Import into Unreal. Enable the Python Editor Script Plugin, then run this from Tools > Execute Python Script. It creates missing assets and overwrites the fields of existing ones, so it is safe to run twice.

    Not runThis script was written from the Python API's naming rules and was not executed. The likeliest things to need a fix are the enum member spellings and the factory property name. help(unreal.TsugiDirection) in the Python console prints the real names.

  4. Tell the game where the network is. A UDeveloperSettings subclass adds a page to Project Settings and reads from DefaultGame.ini. Add "DeveloperSettings" to TsugiXR.Build.cs.

    Set Network to the imported asset in Project Settings. At runtime, GetDefault<UTsugiSettings>()->Network.LoadSynchronous() returns it.

  5. Make sure it is cooked. In Project Settings > Game > Asset Manager > Primary Asset Types to Scan, add an entry: type TsugiNetwork, base class TsugiNetworkDefinition, directory /Game/Data/Levels, and under Rules set Cook Rule to Always Cook. The lines and levels follow through their hard references.

  6. Verify every level. Port LevelCollectionTests as an automation test in TsugiXR/Private/Tests/. This one loads assets, so it needs the editor and cannot run with -NullRHI alone, but it still needs no world.

    Add the checks from the Unity fixture that this sketch leaves out: both tunnel cells carry a fixed piece, and every level has two usable star thresholds or none.

  7. Pin the order. Add a second test that reads network.json from a known path and asserts the flat list of ids matches it, entry for entry. That test is what stops a later re-import from renumbering the game.

Acceptance checks

  • network.json has 24 lines, each with 9 levels.
  • The Content Browser shows 216 level assets, 24 line assets and one network asset.
  • Opening the first level of line 0 shows id simple, display name Ashgate, with Is Tutorial ticked.
  • Tsugi.Levels.EveryShippedLevelIsSound passes: 216 levels, each with exactly one solution inside 5 million nodes.
  • The order test passes.
  • Running the import script a second time changes nothing in source control.
  • A packaged build's log shows the network loading, which proves the cook rule works. Log the level count from the game module's startup to check.

Pitfalls

  • Assets that work in the editor and vanish in a build. The editor loads anything on disk. A packaged game only has what was cooked. Test the cook rule on the device now, not in lesson 18.
  • Renaming an asset is not renaming a level. The asset name is for the Content Browser. The Id field is the save key. Never derive one from the other at runtime.
  • The solver test is slow. 216 solves, the worst around 1.5 million nodes. Expect tens of seconds in a development build. If it takes minutes, your solver's pruning differs from the C#.
  • Board sizes vary. Most boards are 6×6, 7×7 or 8×8, but do not hard-code that anywhere. Width and height come from the level.

Knowledge check

A designer wants a new line between line 3 and line 4. What happens to existing players' saves?

  • Nothing. Saves are keyed by level id.
  • Best times survive, because they are keyed by id, but every level after the insertion changes its flat index, so unlock order and line membership shift.
  • The save file is rejected as corrupt.

Unlocking walks the flat list: a station opens when the level before it in that list has a best time. Insert a line and "the level before" changes for everything after it. Lines are append-only.

Why is the pointer from UTsugiSettings to the network a TSoftObjectPtr?

  • Hard pointers are not allowed in config.
  • A settings object exists from engine start. A hard reference would force the whole network to load with it, before anything needs it; a soft one stores only a path.
  • Soft pointers are cooked automatically and hard ones are not.

It is the other way round for cooking: a soft path alone does not reliably pull an asset into a build, which is why step 5 adds the cook rule.

The Python script sets is_tutorial. What is the C++ property called?

  • IsTutorial
  • bIsTutorial
  • is_tutorial

Python drops the b prefix from booleans and converts the rest to snake case.
